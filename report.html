BÀI TẬP 2: CHUYỂN ĐỔI RESTTEMPLATE SANG FEIGNCLIENT

Đồng bộ hóa kiến trúc giao tiếp Microservices theo phong cách Declarative REST Client tại VietMart
Khóa học: Microservices System Design (Rikkei Education)
Module: order-service → product-service, user-service
Nền tảng: VietMart E-Commerce Platform
Công nghệ: Spring Cloud OpenFeign, Spring Cloud Netflix Eureka, CircuitBreaker

1. Bối cảnh & Mục Tiêu Kỹ Thuật

Sau khi khắc phục thành công lỗi hardcode IP và cấu hình timeout trong ProductServiceClientRT (Bài tập 1), đội ngũ kỹ thuật VietMart quyết định chuẩn hóa toàn bộ các client giao tiếp liên dịch vụ sang Spring Cloud OpenFeign. OpenFeign cho phép định nghĩa giao diện giao tiếp dưới dạng interface khai báo (Declarative REST Client), tích hợp sẵn Eureka Service Registry, Spring Cloud LoadBalancer và cơ chế cô lập lỗi thông qua FallbackFactory.

Đồng thời, hệ thống bổ sung thêm UserClient để order-service truy xuất thông tin người dùng từ user-service phục vụ quá trình xác thực và tạo đơn hàng.

2. So Sánh Imperative Client (RestTemplate) và Declarative Client (OpenFeign)

2.1. Bản chất kiến trúc và cơ chế hoạt động

  • RestTemplate (Imperative / Lập trình Mệnh lệnh): Kỹ sư phải viết rõ từng bước thực thi: khởi tạo hoặc tiêm Bean, ghép chuỗi URL, xử lý kiểu tham số, tuần tự hóa/giải tuần tự hóa JSON, viết các khối try-catch bao quanh từng phương thức để xử lý ngoại lệ HTTP, và trực tiếp gọi hàm fallback. Mô hình này làm tăng đáng kể khối lượng code thừa thãi (Boilerplate Code) và dễ gây phân tán logic xử lý lỗi.
  • OpenFeign (Declarative / Lập trình Khai báo): Kỹ sư chỉ cần khai báo một Java Interface với các annotation quen thuộc của Spring MVC (@GetMapping, @PathVariable). Tại thời điểm ứng dụng khởi động, OpenFeign sử dụng JDK Dynamic Proxy để tự động tạo Bean thực thi ngầm. Việc kết nối Eureka để tra cứu Service ID, cân bằng tải Round-Robin, kích hoạt Fallback khi quá thời gian timeout đều do framework điều phối tự động và minh bạch.

2.2. Bảng thống kê định lượng số dòng code (Lines of Code - LOC)

Thành phần chức năng ProductServiceClientRT (RestTemplate) ProductClient (OpenFeign) Đánh giá tối ưu
Khai báo lớp / Interface Class (@Component) Interface (@FeignClient) Loại bỏ ràng buộc implementation
Khai báo trường & Constructor Injection 12 dòng (RestTemplate, URL, @Autowired) 0 dòng Tiết kiệm 100%
Phương thức getById(Long id) 18 dòng (URL template, getForObject, 2 khối catch) 2 dòng (@GetMapping + method signature) Giảm ~89% số dòng
Phương thức getAll() 15 dòng (URL, mảng chuyển đổi, try-catch) 2 dòng (@GetMapping + method signature) Giảm ~87% số dòng

Nhận xét chuyên môn: OpenFeign giúp cắt giảm gần 80% khối lượng mã nguồn lặp lại, triệt tiêu nguy cơ sai sót do gõ nhầm chuỗi URL và chuẩn hóa toàn bộ các giao tiếp HTTP trong hệ sinh thái VietMart theo một hợp đồng (Contract) duy nhất.

3. Lập Luận Kỹ Thuật: Khi Nào Nên Dùng Mỗi Cách?

Tiêu chí lựa chọn Sử dụng OpenFeign Sử dụng RestTemplate / HttpClient
Phạm vi áp dụng Giao tiếp giữa các Microservice nội bộ (Internal Service-to-Service). Giao tiếp với API bên thứ ba (External Third-Party APIs như VNPay, ZaloPay, Stripe, GHTK).
Service Registry Tích hợp sâu với Eureka Registry, tự động phân giải Service ID. Phù hợp với các Domain/IP cố định, không nằm trong Eureka Service Registry.
Khả năng tùy biến tầng thấp Trừu tượng hóa cao, hạn chế can thiệp chi tiết vào socket, TLS handshake đặc biệt. Toàn quyền cấu hình Connection Pool, Proxy nâng cao, Mutual TLS (mTLS), custom multipart stream.
Bảo trì & Mở rộng Rất cao; thêm API mới chỉ cần thêm 1 dòng interface; dễ dàng chia sẻ Contract DTO. Thấp hơn khi mở rộng số lượng API lớn; đòi hỏi viết nhiều mã nguồn lặp lại.
Circuit Breaker & Fallback Hỗ trợ sẵn cấu hình declarative qua fallbackFactory của Resilience4j. Phải tự bao bọc bằng decorator @CircuitBreaker hoặc các khối try-catch thủ công.

4. Mã Nguồn Cài Đặt Chi Tiết

4.1. Interface ProductClient.java

@FeignClient(name = "product-service", fallbackFactory = ProductClientFallbackFactory.class)
public interface ProductClient {

    @GetMapping("/api/products/{id}")
    ProductInfo getById(@PathVariable("id") Long id);

    @GetMapping("/api/products")
    List getAll();
}

4.2. Interface UserClient.java

@FeignClient(name = "user-service")
public interface UserClient {

    @GetMapping("/api/users/{userId}")
    UserInfo getUserById(@PathVariable("userId") Long userId);
}

4.3. Lớp ProductClientFallbackFactory.java

@Component
@Slf4j
public class ProductClientFallbackFactory implements FallbackFactory {

    @Override
    public ProductClient create(Throwable cause) {
        log.error("ProductClient fallback kích hoạt do lỗi: [{}], chi tiết: {}",
                cause.getClass().getSimpleName(), cause.getMessage(), cause);

        return new ProductClient() {
            @Override
            public ProductInfo getById(Long id) {
                log.warn("Kích hoạt fallback cho getById(id={}). Nguyên nhân: {}", id, cause.getMessage());
                return ProductInfo.builder()
                        .id(id)
                        .name("Sản phẩm tạm thời không khả dụng (Fallback)")
                        .price(BigDecimal.ZERO)
                        .stockQuantity(0)
                        .description("Thông tin sản phẩm tạm thời gián đoạn do sự cố kết nối tới product-service.")
                        .category("UNKNOWN")
                        .status("UNAVAILABLE")
                        .build();
            }

            @Override
            public List getAll() {
                log.warn("Kích hoạt fallback cho getAll(). Nguyên nhân: {}. Trả về danh sách rỗng.", cause.getMessage());
                return Collections.emptyList();
            }
        };
    }
}

4.4. Cấu hình application.yml

spring:
  application:
    name: order-service
  cloud:
    openfeign:
      circuitbreaker:
        enabled: true
      client:
        config:
          default:
            connectTimeout: 2000
            readTimeout: 3000
            loggerLevel: full
          product-service:
            connectTimeout: 2000
            readTimeout: 3000
            loggerLevel: full
          user-service:
            connectTimeout: 2000
            readTimeout: 3000
            loggerLevel: basic

eureka:
  client:
    service-url:
      defaultZone: http://localhost:8761/eureka/

6. Kết Luận

Việc chuyển đổi từ RestTemplate sang FeignClient mang lại bước đột phá về tính thẩm mỹ, khả năng mở rộng và độ ổn định của hệ thống Microservices VietMart:

  • Code sạch, ngắn gọn, giảm hơn 78% số dòng lệnh lặp đi lặp lại.
  • Tách bạch ranh giới trách nhiệm giữa việc định nghĩa API và xử lý suy thoái hệ thống (Fallback).
  • Dễ dàng kiểm soát thời gian chờ (Timeout) và ghi nhận log phục vụ việc vận hành hệ thống thông suốt.
